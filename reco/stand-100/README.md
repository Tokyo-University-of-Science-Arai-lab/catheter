# stand-100 (旧 80-reco / reco-80-stand / stand-80)

catheter-100 の5画像(1,2,3,4,5) x 20クエリ = 100件 認識精度検証。当初は画像4の
アノテーションが不完全で80件評価だったが、2026-08-21に画像4のアノテーションが揃い
100件評価に更新した。同日 `reco/` 配下へ再編し、depth付き実撮影(`depth_shots/`)も追加した。

## フォルダ構成

```

annotations/instances_default_80.json
                                     元の instances_default.json から画像4を除いた
                                     正解アノテーション(COCO形式, 80件、当初評価分)
annotations/instances_default_100.json
                                     2026-08-21、画像4のアノテーションが用意されたため
                                     instances_default_80.jsonに画像4の20件をマージした
                                     全5画像・100件版(image_id=4、ann_id 86-105)
depth_shots/                        RealSenseで実撮影したdepth付きデータ(2026-08-21追加)
  1/, 2/, 3/, 4/, 5/                  各棚配置ごとの after_init_rgb.png / after_init_depth.npy
                                     / camera_params.json。images/の同番号画像と180度回転の
                                     関係にある(../README.md参照)。旧"4"(初回撮影)と
                                     "4_new"(再撮影)が両方あったが、2026-08-21にユーザー確認の上
                                     "4_new"を正としてリネーム、旧"4"はごみ箱へ退避した。
                                     画像4のアノテーションデータは作成中(2026-08-21時点)。
                                     (旧"画像5つまとめ"フォルダは images/{1-5}.png と完全に
                                     同一の重複コピーだったため、ごみ箱へ退避済み)
outputs/                             catheter_recognition_report.xlsx 等、100件評価一式の生成物
                                     (2026-08-21、画像4を含めて再生成。Excelは画像ごとに
                                     シート分割: img1〜img5)
scripts/                             生成・再評価に使ったスクリプトの参照用コピー
                                     (実行は元の場所 ~/ダウンロード/catheter_test80/catheter/scripts/
```

マスタJSONはこのフォルダには置かず、`reco/master_catheter_reco.json` を参照する。

`catheter_recognition_report.xlsx`（IoU精度・幅(px)精度・識別精度をまとめたExcel）を
他のデータセットや別セッションで同じ手順で再現したい場合は
[`scripts/README.md`](scripts/README.md) を参照。

## 評価結果(2026-08-20に80件で実施→2026-08-21、画像4を追加し100件に更新)

| 指標 | 値(100件) | 値(旧80件、参考) |
|---|---|---|
| IoU≥0.5でマッチ | 79/100 (79.0%) | 78/80 (97.5%) |
| 幅誤差(px) | MAE 5.54px | MAE 5.61px |
| 識別精度(改善後: 多段query+ハンガリー法) | 67/76 (88.2%)※ | 67/76 (88.2%) |

※識別精度の比較可能件数(76件)は旧80件版と同数のまま変わっていない
(画像4はIoUマッチが1/20しかできず、識別比較の対象になるペアがほぼ増えなかったため)。

**画像4だけIoU≥0.5マッチが1/20と極端に低い**(他画像は18〜20/20)。
`catheter-100/images/default/4.png`(このpx評価が使う静止画)は、`depth_shots/4/`
(2026-08-21に"4_new"から改名した再撮影データ)とは別の、当初からある画像である点に
注意。再撮影の理由になった何らかの問題(要確認)が、この静止画側にも影響している
可能性がある。

詳細は [../../HANDOFF_20260820_catheter100_sam_eval.md](../../HANDOFF_20260820_catheter100_sam_eval.md) を参照。

## SAM重複マスクの調査結果(2026-08-21、詳細は上記HANDOFF参照)

「20件のGTに対し予測33〜38件」の重複は、当初想定していた
「同じ箱を重なって複数マスクで検出」ではなく、**ピクセル単位では一切重ならない
(IoU=0)、ラベル部分と本体などに分割検出されたフラグメント**であることが判明。
このためIoUベースのマスクNMSは無力(実測: 除去0件)。bbox包含率でのクラスタ化＋
OCRテキスト共有も試したが、無関係な物体まで巻き込んで識別精度を悪化させたため
撤回した(67/76→65/73に悪化)。現状、この問題は識別精度への影響が2/80件程度と
限定的なため、無理に修正せず既知の限界として記録するにとどめている。

## 実mm幅計測(get_book_points.py本番パイプライン)の検証結果(2026-08-21)

`depth_shots/`を使い、`get_book_points.py`本番の3D計測パイプラインで実mm幅を測定し
マスタJSONの正解値と比較した。100件(5画像×20品目)、MAE 9.06mm、10mm未満74%。
詳細・環境修正内容は [`width_eval_summary.md`](width_eval_summary.md) を参照。
